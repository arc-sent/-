# nSigmaBot — Telegram-бот для VK-заказов (API prmotion.me)

Многопользовательский бот: каждый пользователь проходит регистрацию своим
API-ключом (ключ хранится в SQLite), после чего управляет **только VK-сервисами** —
баланс, список сервисов, создание заказов и проверка статусов.

## Возможности

- 🔐 **Регистрация** — при `/start` бот просит API-ключ, проверяет его запросом
  баланса и сохраняет в БД. У каждого пользователя свой ключ.
- 💰 **Баланс** — баланс аккаунта, привязанного к ключу
- 📋 **Сервисы** — только **клип-сервисы VK**, разбитые по категориям
  👀 Просмотры / 👍 Лайки / 👥 Подписки (ID, цена, лимиты)
- 🛒 **Создание заказа** — пошаговый мастер; поля запрашиваются по типу сервиса
- 💧 **Капельная доставка (drip-feed)** — большой заказ дробится на равные части и
  докручивается равномерно 3–4 дня, чтобы график рос плавно и «живо»
- 🔎 **Статус заказа** — по одному ID или нескольким (через запятую)

## Установка

```powershell
py -3.10 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt

copy .env.example .env
#   затем открой .env и заполни BOT_TOKEN (и при желании ADMIN_IDS)
```

Переменные окружения (`.env`):

- `BOT_TOKEN` — токен от [@BotFather](https://t.me/BotFather)
- `ADMIN_IDS` — *(опционально)* список Telegram ID через запятую. Если задан —
  регистрироваться и пользоваться ботом смогут только эти ID. Пусто — регистрация
  открыта всем.
- `API_URL` — базовый URL API (по умолчанию `https://api.prmotion.me/v1`)
- `DEFAULT_CURRENCY` — `RUB` или `USD`
- `DB_PATH` — путь к файлу SQLite (по умолчанию `bot.db`)

> ⚠️ **API-ключ больше не хранится в `.env`.** Каждый пользователь вводит свой
> ключ в самом боте — он сохраняется в БД (`bot.db`). Файл БД содержит ключи в
> открытом виде: не коммить его и ограничь доступ к серверу.

## Запуск (локально)

```powershell
.\.venv\Scripts\python.exe bot.py
```

При первом `/start` бот попросит прислать API-ключ.

## Деплой в Docker

Нужен установленный Docker (и Docker Compose). На сервере:

```bash
# 1. Скопируй проект и создай .env из шаблона
cp .env.example .env
nano .env            # впиши BOT_TOKEN (и при желании ADMIN_IDS)

# 2. Собери и запусти в фоне
docker compose up -d --build

# 3. Логи / статус / перезапуск / остановка
docker compose logs -f
docker compose ps
docker compose restart
docker compose down          # остановить (данные в volume сохранятся)
```

Особенности:
- **БД в volume `botdata`** (`/data/bot.db` внутри контейнера) — ключи пользователей и
  запланированные капельные докрутки переживают перезапуск/пересборку.
- `restart: unless-stopped` — бот сам поднимется после перезагрузки сервера или падения.
- `.env` и `*.db` не попадают в образ (см. `.dockerignore`) и в git (см. `.gitignore`).
- Часовой пояс капельной доставки задаётся не системным временем, а `DRIP_TZ_OFFSET`
  в `config.py`, поэтому не зависит от TZ сервера.

Бэкап БД из volume:

```bash
docker run --rm -v nsigmabot_botdata:/data -v "$PWD":/backup alpine \
  cp /data/bot.db /backup/bot.db.bak
```

## Команды

| Команда | Действие |
|---|---|
| `/start` | Меню (или регистрация, если ключа ещё нет) |
| `/register` | Сменить сохранённый API-ключ |
| `/logout` | Удалить свой ключ из бота |
| `/balance` | Баланс |
| `/services` | Список VK-сервисов |
| `/order` | Создать заказ |
| `/status <id>` | Статус заказа (можно `id1,id2,...`) |
| `/drips` | Активные капельные доставки и их прогресс |
| `/cancel` | Отменить текущий диалог |

## Структура

| Файл | Назначение |
|---|---|
| `bot.py` | Хэндлеры, меню, регистрация, middleware-авторизация, FSM заказов |
| `api.py` | Асинхронный клиент API (ключ передаётся в каждый вызов) |
| `db.py` | Хранилище пользователей в SQLite (`telegram_id → api_key`) |
| `service_types.py` | Карта «тип сервиса → требуемые поля» |
| `catalog.py` | Курируемый список сервисов: ID → (группа, русское название) |
| `grouping.py` | Порядок и подписи категорий (просмотры/лайки/подписки) |
| `drip.py` | Разбивка заказа на равные части во времени (drip-feed) |
| `keyboards.py` | Клавиатуры (меню, категории, доставка, подтверждение) |
| `config.py` | Настройки из `.env` + фильтр платформы (`SERVICE_PLATFORM = "vk"`) |

## Заметки

- **Какие сервисы показывать** — задаётся явным списком в `catalog.py`:
  `ID сервиса → (группа, «Русское название»)`. Только эти сервисы попадают в меню и
  доступны для заказа; цена/лимиты подтягиваются из API по ID. Добавить сервис —
  дописать строку, убрать — удалить строку. Русское название показывается как на
  сайте.
- **Цена.** Цена за 1 шт = `rate / RATE_PER_UNITS` (по умолчанию делитель `10`,
  например `rate 0.09 -> 0.009 ₽/шт`). Сумма заказа = `цена_за_штуку × количество`.
  Делитель задаётся в `config.py` (`RATE_PER_UNITS`).
- **Категории** (👀 Просмотры / 👍 Лайки / 👥 Подписки) — порядок и подписи в
  `grouping.py` (`GROUPS`), а к какой категории относится сервис — во втором поле
  строки `catalog.py`. Пустая категория показывается с пометкой «пока нет сервисов».
- Если API вернёт неизвестный `type`, бот по умолчанию спросит `link` + `quantity`.
  Точный набор полей задаётся в `SERVICE_FIELDS` в `service_types.py`.
- **Капельная доставка (drip-feed).** У API нет встроенного drip-feed, поэтому
  расписание ведёт сам бот. При заказе сервиса с количеством можно выбрать «⚡ Сразу»
  или «📆 3/4 дня». Общий объём делится на равные части через равные интервалы по
  всему окну (линейный график), размер части не меньше `min` сервиса. Под-заказы
  хранятся в таблице `drip_runs` (SQLite), фоновый планировщик каждые
  `DRIP_TICK_SECONDS` отправляет наступившие докрутки — это переживает перезапуск
  бота. Прогресс — команда `/drips`.
  - **Активные часы + живой разброс.** По умолчанию докрутки идут только днём —
    `DRIP_ACTIVE_HOURS = (9, 23)` по времени `DRIP_TZ_OFFSET` (UTC+3, Москва): ночью
    пауза. Границы окна и моменты докруток каждый день случайно смещаются на
    `DRIP_JITTER_MINUTES` (по умолчанию ±55 мин) — старт то в 8:12, то в 9:40, финиш
    то в 22:30, то в 23:41, интервалы неровные. Круглосуточный режим —
    `DRIP_ACTIVE_HOURS = None` (там тоже добавляется джиттер).
  - **Длительность по категориям.** Просмотры/лайки растягиваются на `DRIP_DAYS_CHOICES`
    (3/4 дня), подписчики — на сутки (`DRIP_DAYS_BY_GROUP = {"subs": (1,)}`). Для любой
    группы можно задать свои варианты в `DRIP_DAYS_BY_GROUP`.
  - Прочие настройки: `DRIP_RUNS_PER_DAY`, `DRIP_TICK_SECONDS`.
```
